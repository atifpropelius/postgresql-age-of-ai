# Tech talk session format

Source: format supplied by the tech lead/company owner in the conversation on 2026-10-15. Use this file when editing or rehearsing FS-03. Keep the question bank and quiz in a separate file; the presentation itself must not contain Q&A or quiz screens.

## Session format (60 minutes)

| Segment | Time | Notes |
| --- | --- | --- |
| Talk | 30–45 min | Slides plus real code or a live demo. Hard stop at 45 — the host holds the clock. |
| Q&A | 5 min | Questions the quiz will not cover. The host parks anything that turns into a debate. |
| Quiz | 10–12 min | 8–10 questions, run live (Kahoot / Slido / Google Forms quiz mode). Presenter answers disputes on the spot. |
| Feedback form | 2 min | Anonymous link posted in Slack. Open for 24 hours. Fill it before you leave the room, ideally. |

The ranges can total more than 60 minutes at their maximum. For an actual 60-minute booking, rehearse a roughly 35–40-minute talk and leave the rest for Q&A, quiz, feedback, and transitions. The host's 45-minute hard stop still applies. Questions and quiz content belong in a separate file/tool, outside the main deck.

## FS-03 application

- Topic: **Supabase as a backend: what runs where** (Tier 1).
- Main deck: 20-slide, 40-minute route through one task app, including one brief external gateway example, five concise Studio menu slides and a production-habits recap. Put field-by-field dashboard details, SQL, CLI and speaker guidance in separate presenter documents; illustrations are conceptual unless explicitly connected to a live demo project.
- Keep slides inside the talk segment. No Q&A, quiz, or feedback form slide in the main route.
- Rehearse the final timings against this format before presenting.
